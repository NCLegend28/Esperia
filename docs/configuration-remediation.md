# Configuration and topic independence

This remediation replaces silent quantum-company defaults with a separately metered, question-driven source-planning call for Codex-enabled research. Explicit manifests and verified archives bypass that step. Local-only workflows require explicit evidence inputs.

Fixed host lists were replaced with configurable exact-host restrictions plus public-address DNS validation and pinned HTTPS connections. The core network checks are not configurable bypasses. Discovery uses Unicode query terms including short sector words, with domain terms available through explicit profiles.

`settings.py` is the source of defaults and cross-field validation. Configuration travels explicitly through providers, collection, analysis, accounting and repairs. Role models, reasoning, templates/checklists, storage, ranking, timeouts, collection limits, output budgets and execution policy are overridable. Historical wire schemas and compatibility identifiers remain fixed contracts. API endpoints remain bound to their named provider adapters.

Every drafting backend selects existing excerpts, including deep-mode analysts. Stage roles are explicit rather than inferred from stage-name prefixes. Resolved settings are saved with jobs and included in cache identity. Parent repair profiles are inherited unless explicitly overridden; operational configuration is always persisted with the child.

The earlier coverage, preflight and repair-diagnostic fixes are retained. Existing manifests are preserved only as opt-in examples. No existing job, cache or ledger was rewritten. Previously rejected quotation jobs remain rejected; they are not automatically rerun or accepted.

Validation uses simulated providers and HTTP transports, real PDF extraction and temporary ledgers. Tests cover cross-domain hosts, private/mixed DNS rejection, TLS hostname preservation, energy/acronym scoring, settings overrides, model/profile cache invalidation, metered source planning, uncertain search failure, local-only isolation and earlier approval gates. Live subscription generation is not part of the regression suite.

Validation result: 136 tests passed; Ruff, Black and strict Mypy passed. The package source distribution and wheel built successfully. Dependency audit found no known vulnerabilities (editable Esperia itself excluded). No live subscription generation was performed.
